Three promises

A folder, a loopback port, and the standard library.

Your files stay yours

A project is a markdown file you can read, grep, edit in any editor and keep in git. The application renders those files and writes them back; it never takes custody of them. Delete it tomorrow and your work is still there, in plain text.

No cloud, no account

It binds to loopback by default and works with the network cable out. Expose it and it demands a shared token on every request. Nothing is uploaded, because there is nowhere to upload it to.

No build step, no dependencies

Python 3.11 and its standard library, two stylesheets and two scripts. No npm, no bundler, no framework to upgrade at 2am. Clone it and run it. That is the whole installation.

What it does

A chart for planning, a list for the corridor.

The chart

One ranked list, with DONE and DROPPED at the bottom. Every project carries a coloured band that fades as the list goes down, so the order reads at a glance. Drag a project to reorder it, or onto a group to finish it; drag a bar to move it, or either edge to resize it, in whole working days. Zoom from a day per column to two years on one screen.

Every project, in place

Status, deadlines, platforms, Jira/Confluence/Figma links, attachments of any type, milestones on the lane, and an action list with history. Every value reads as information and becomes an editor when you ask it to, with an explicit Save and a delete that always asks.

The whole vault as one document

A hierarchy view that shows every value every card holds, and a markdown tab that is every card concatenated, editable in one go and downloadable as a monthly snapshot. A block with an unknown id creates a card; a card whose block is missing is never deleted.

A phone with its own interface

On a phone it is a list of project cards with the span, the milestones and what is asking for attention. Tap one and the project takes the screen, notes first, with every value editable where it stands.

The format

This is the database.

One file per project. The title is the name, every field is a - key: value item, a group is two spaces deeper, free text lives under ## Notes. Nothing is quoted, nothing is escaped, and a key the application has never heard of survives every save.

Self-host

Thirty seconds, and it is yours.

git clone https://github.com/stangoldbear/ganttbit.git
cd ganttbit
python3 dashboard.py --vault sample-vault --port 8099

Open http://localhost:8099. That runs against the sample vault, a fictional organisation used as the demo and as the test fixture. Point settings.toml at your own folder and run python3 dashboard.py. To reach it from your phone, bind it to your network and it will mint an access token for you.

The model

Free, and that is the whole product.

Everything on this page is in the repository, under MIT, in full, forever. There is no trial period, no reduced plan and no feature held back. If you can run a command, you never have to pay us anything.

One day there may be a paid way to have somebody else run it for you: a machine that is always on, with backups and a URL that is there tomorrow morning. There may also be a way for several people to share one vault. Neither exists yet, and this page will not pretend otherwise. When they do, the self-hosted version will be exactly what it is today: complete.

Questions you should ask

What is the catch.

Is the free version actually the whole thing?

Yes. The repository is the product: the chart, the editing, the markdown format, the phone, the snapshots. What a paid plan would sell is somebody running the software for you, on hardware you do not have to think about.

Where is my data, exactly?

In the folder you pointed the application at, as markdown files, one per project, with attachments beside them. There is no database and no hidden index. Back it up by copying a folder; version it by committing one.

Can you see any of it?

No. The self-hosted application makes no outbound request of any kind: it has a content security policy that forbids one and no telemetry to send. On the hosted plan we would hold your files the way any host does, and you can leave with them at any time.

What if this project stops being maintained?

You keep a working copy of a program with no dependencies and no build step, and a vault of plain markdown that any editor can open. The worst case is a folder of files that outlives the software, which is why the format is what it is.

Will it stay free once there is a paid plan?

The application stays exactly as it is: MIT, complete, self-hostable. Anything paid would be somebody running it for you, or several people sharing one vault. Features already in your copy stay in it.

Why not just use a spreadsheet, or a tracker?

Because a spreadsheet does not draw a delivery plan, and a tracker owns your data, charges per seat and still cannot tell you what is blocked this week without four clicks. This is one screen, built for one person who has to answer that question all day.
